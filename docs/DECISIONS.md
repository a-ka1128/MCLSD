## 1. 스틱스 격차 — 5성에서 혼자 뒤처진다

### 지금 상태 (`tools/calc_power_ratio.py` 실측)

| 유물 | 1성 | 5성 | 평균 대비 |
|---|---:|---:|---:|
| 스틱스 | **35.5** | **81.2** | **−13%** |
| 이지스 | 32.5 | 87.0 | −7% |
| 파나케이아 | 30.3 | 90.9 | −3% |
| 타이탄 | 33.6 | 92.2 | −2% |
| 게볼그 | 35.0 | 92.7 | −1% |
| 시리우스 | 33.6 | 100.8 | +8% |
| 솔라리스 | 34.0 | 102.1 | +9% |
| 셀레스티아 | 34.1 | 102.2 | **+9%** |

**1성에서는 스틱스가 2등인데 5성에서는 꼴찌다.** 편차가 ±12% → ±26% 로 벌어졌다.

### 왜 그런가

성역 축복의 Strength I 은 **덧셈 +3.0** 이고, 이건 `GLOBAL_POWER = 1.8` 을 안 탄다.
그래서 실효 배수가 이렇게 갈린다:

```
실효 배수 = (기본치 × 1.8 + 3.0) / (기본치 + 3.0)
```

기본치가 작을수록 분모에서 +3.0 의 몫이 커져 배수가 희석된다. 스틱스는 기본치가 제일 낮고
평타 비중이 제일 높아(= +3.0 을 가장 많이 받는 무기라) 가장 크게 손해를 본다.
1성에서 2등이던 것도 같은 이유다 — 그때는 덧셈이 이득이었다.

### 선택지

| | 무엇을 하나 | 결과 | 비용 |
|---|---|---|---|
| **A** | 그대로 둔다 | 편차 ±26% 유지 | 0 |
| **B** | 스틱스 기본치 ×1.15 | 5성 81 → 93 (평균) · **1성 35.5 → 39.5 로 압도적 1위** | 상단(백어택·크리) 대역 50~70 → 57~80 으로 같이 뜀 |
| **C** | 스틱스만 축복 덧셈 +3.0 → +4.5 | 5성 ≈ 85 (편차 ±18%) · 1성은 거의 그대로 | 「축복이 직업마다 다르다」는 설정이 생긴다 |
| **D** | `GLOBAL_POWER` 를 낮추고 보스 체력 전면 재역산 | 근본 원인(덧셈 희석)이 줄어든다 | 보스 4종 체력·유지율 전부 다시 |

**B 의 함정이 중요하다.** 5성을 맞추면 1성이 어긋난다. 두 끝을 동시에 맞추려면 덧셈 항을
건드리는 C 쪽이어야 한다.

> ⚠️ **B 를 고르면 50~70 대역이 같이 움직인다.** 그 대역은 당신이 직접 잡은 값이라
> 내가 임의로 못 건드린다. B 를 고를 거면 그 대역을 새로 잡을지도 같이 말해줘야 한다.

**추천: C.** 상단을 안 건드리면서 원인(덧셈 항)을 정확히 겨냥한다. 설정상의 어색함은
「스틱스는 별빛을 더 많이 받는다」 한 줄이면 메워진다.

## 2. 몹 스케일링의 「적대」 판별 — 철골렘이 세진다

### 지금 상태

`ls_mobscale.js` 의 `msIsHostile()` 은 **공격력 속성이 있으면 적대**로 본다.

```js
return e.getAttribute('minecraft:generic.attack_damage') != null
```

원래는 `MobCategory == monster` 를 1순위로 보려 했는데, 그 코드는 `e.getType()` 이
id 문자열이라 처음부터 예외만 던지고 있었다(2026-07-25 에 죽은 경로로 확인·제거).

그래서 판별이 의도보다 **넓다.** 이런 것들이 관문 진행도에 따라 같이 세진다:

| | 세지는 게 맞나 |
|---|---|
| 철골렘 · 눈사람 | ❌ **플레이어가 만든 것이다.** 내 방어 수단이 강해지는 건 상관없지만, 마을 주민이 만든 골렘도 세진다 |
| 늑대 · 북극곰 · 벌 | 🤔 **실제로 덤빈다.** 세지는 게 오히려 맞을 수도 |
| 좀비 · 스켈레톤 등 | ✅ 의도대로 |

### 선택지

| | 무엇을 하나 | 비용 |
|---|---|---|
| **A** | 그대로 (넓게) | 0 — 여태 이 상태로 돌아왔다 |
| **B** | 철골렘·눈사람만 명시 제외 | 2줄. 「플레이어가 만든 것은 안 센다」는 규칙이 명확하다 |
| **C** | `MobCategory == monster` 로 좁힌다 | 모드 쪽에 `LS.isMonster(entity)` 다리를 하나 놓으면 된다(반나절 미만) · 늑대·북극곰이 빠진다 |

**추천: B.** 규칙이 한 문장으로 설명되고("플레이어가 만든 것은 세상의 일부가 아니다"),
늑대·북극곰처럼 실제로 덤비는 놈들은 그대로 남는다. C 는 «덤비는데 안 세지는» 경우를 만든다.

### 4-2. 재감정

싸면 원하는 게 나올 때까지 돌리는 노가다가 되고, 비싸면 나쁜 걸 뽑은 사람이 그대로 굳는다.

| | 안 | 결과 |

| **B** | 균열 정수 3개 · 무제한 | 정수가 마을 재건과 경쟁하므로 «돌릴수록 마을이 늦어진다»가 비용이 된다 |
| **C** | 각성 단계당 1회만 (무료) | 노가다 불가 · 한 번의 만회 기회 |

**추천: C.** 정수를 비용으로 쓰면 결국 정수 파밍이 늘어난다. 횟수 제한이 노가다를
구조적으로 막는 유일한 방법이고, 「한 번은 다시 뽑을 수 있다」가 운의 격차도 충분히 줄인다.

### 4-3. 15종 전부 갈지

별의 도약·별똥 파편·재림 셋은 **Java 훅이 필요하다.** 나머지 12종은 KubeJS 로 된다.

| **B** | 15종 한 번에 (Java 까지) |

**추천: A.** 12종이면 이미 조합이 충분히 갈린다. 남은 셋은 «있으면 좋은 것»이라
