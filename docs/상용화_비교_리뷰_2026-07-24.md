## 0. 한 줄 요약

**"모드 조립 서버"가 아니라 하나의 완성된 협동 캠페인 게임을 만들었다.** 공동 금고·마을 발전·밤 공성·균열 원정·폐막 시상식으로 이어지는 자체 게임루프는 상용 어드벤처 모드팩에서도 보기 드문 수준의 설계다. 다만 **(1) 서버 틱을 죽이는 커스텀 모드 크래시**, **(2) 제거된 모드가 남긴 로그·레시피 오염**, **(3) 모든 진행 상태를 오버월드 NBT 한 곳에 몰아넣은 저장 구조** 이 세 가지가 "상용 수준 안정성"을 막는 실질적 병목이다.

## 1. 이 서버가 실제로 만든 것 (정체성)

일반적인 1.21.1 어드벤처 팩(Terralith + YUNG's + Dungeons Arise + Cataclysm + Apotheosis + Better Combat…)을 베이스로 깔았지만, 진짜 정체성은 그 위에 얹은 **자체 KubeJS 게임 시스템**에 있다:

| 시스템 | 파일 | 역할 |
|---|---|---|
| 공동 금고 | `ls_income.js` | 개인 지갑이 아닌 **팀 공유 계좌** — 협동이 곧 파워 스케일링 |
| 마을 발전 | `ls_town.js` | 4트랙 × 4레벨(방벽/공방/성소/구역), 금고+정수+자원 게이팅 |
| 밤 공성 | `ls_siege.js` (918줄) | 위협도 0~15, 3일 주기 공성 + 12일 대공세, 성벽 내구도, 최종장 리치전 |
| 균열 원정 | `ls_rift.js` | 성역 기준 링 거리에 보스 제단 4단계 → 월드티어 상승(Apotheosis) |
| 균열 열쇠 | `ls_keys.js`+`ls_items.js` | Vault Hunters식 "열쇠로 던전 개방" 반복 엔드게임 |
| 정화 봉화 | `ls_beacon.js` | 영토 수복 가시화 — 반경 잡몹 정화 + 위협 하한 완화 |
| 몹 스케일링 | `ls_mobscale.js` | 진행도(rf_progress)에 따라 세상 잡몹도 같이 험해짐 |
| 칭호/통계/폐막식 | `ls_title.js` `ls_stats.js` | 명예 시스템 + **섭종 콘서트식 자동 시상 연출** |
| 각성/운명/현상금/카지노/구출/유물 | `ls_ascend/fate/bounty/casino/rescue/relic.js` | RPG 성장·랜덤성·사이드 콘텐츠 |
| 낮밤 커스텀 | `ls_daynight.js` | 하루 20분(낮5/저녁4/밤7/새벽4), 공성 주기와 정확히 동기화 |

여기에 **FTB Quests 5챕터(~950줄): sanctuary → frontier → region → expedition → lastgate** 가 진행의 뼈대를 잡고, 커스텀 자바 모드 `lsrelics`가 별의 유물 4종(활/방패/도끼/지팡이 하이브리드)을 제공한다.

**포지셔닝:** 오픈월드 생존팩이 아니라 **시작과 끝이 있는 8인 협동 타워디펜스 RPG 캠페인**. `pvp=false`, `max-players=8`, `difficulty=hard`, 폐막식/피날레 존재가 이를 뒷받침한다.

## 2. 강점 — 상용 대비 경쟁력 있는 것

- **자체 게임루프의 완성도.** "낮에 원정·자원 → 저녁 준비 → 밤 공성 방어 → 금고로 마을 성장 → 더 센 원정" 순환이 시간(낮밤)·재화(Ducat)·진행(정수/월드티어)·공간(봉화 수복)으로 서로 맞물린다. 상용 팩 대부분은 이런 메타루프 없이 "모드 나열 + 퀘스트북"에 그친다.
- **협동을 파워로 강제한 경제 설계.** 공동 금고 + 마을 발전은 경쟁(PvP·개인부농)이 아니라 협동에서 강함이 나오게 만든다 — 사설 소규모 서버에 이상적. (참고: 상용 SMP는 대개 개인 경제라 소규모에선 빈부격차·이탈이 생김)
- **"끝맺음" 설계.** `ls_stats.js`의 자동 폐막 시상식은 상용 서버가 거의 안 하는 부분. 소규모 시즌제 서버의 리텐션·재접속 동기로 강력하다.
- **밸런스 튜닝 자산의 월드 리셋 내성.** `ls_config.js`가 튜닝값을 월드 밖에 두고, 라이브 오버라이드는 NBT에 두는 이원화 — 시즌 반복 운영을 이미 염두에 둔 구조.
- **정직한 KubeJS 엔지니어링.** 인벤토리 API 대신 `/clear count 0`으로 보유량 확인, 열쇠 이중소모 방지 가드, 보스/잡몹 이중 스케일 방지 등 실전 함정을 피해감. 로드 로그상 **KubeJS 스크립트 0 error / 0 warning**.
- **월드젠 스택이 상용 어드벤처 팩 수준.** Terralith + Regions Unexplored + Structory(+Towers) + Dungeons Arise + Dungeons & Taverns + YUNG's 풀세트 + Explorify + Towns&Towers. 탐험 밀도는 상용 "Better MC / Prominence"급.

## 4. 발견된 문제점 (심각도 순)

### 🔴 Critical — 서버가 죽는다

1. **`lsrelics` 커스텀 모드가 서버 틱 루프를 크래시.**
   `crash-2026-07-23_15.43.30-server.txt`:
   ```
   java.lang.IllegalArgumentException: Invalid weapon firing an arrow
     at com.laststardust.relics.ArrowStormManager.onServerTick(ArrowStormManager.java:56)
   ```
   유물의 "화살 폭풍" 기믹이 **weapon ItemStack 없이(null/EMPTY) `Arrow`를 생성**해 바닐라 검증(`AbstractArrow.<init>`)에서 터짐. 서버 틱 스레드에서 발생 → **전체 서버 다운**. 같은 날 1분 뒤 워치독 크래시(`tick took 60000004 seconds`)도 같은 계열의 행(hang)일 가능성이 높다.
   → **1순위 수정.** `ArrowStormManager.onServerTick`에서 화살 생성 시 발사 주체 무기 스택을 항상 유효 아이템(예: 소환자 손 아이템 또는 `Items.BOW` 기본 스택)으로 넘기고, null 가드 추가. lsrelics 소스가 있으면 거기서, 없으면 KubeJS로 대체 구현.

### 🟠 High — 운영 리스크

2. **제거된 모드의 잔재가 데이터/로그를 오염.** `latest.log`에 다음이 로드 때마다 발생:
   - Quark(`GoldToolsHaveFortuneModule`), Ars Nouveau(`SpellCrossbow`), FramedBlocks, Patchouli/JEI 클래스 mixin 실패
   - `apotheosis:book` 레시피 파싱 실패(`patchouli:guide_book` 없음)
   - advancement 로드 실패: `dungeons_arise:find_thornborn_towers`, `find_fishing_hut`, `minecraft:give_quest_trader_trade`
   - `expandeddelight:add_loot_sniffer_digging` 루트 모디파이어 디코드 실패
   개별로는 non-fatal이지만, **레시피/도전과제/루트가 조용히 누락**되고 로그 노이즈가 실제 오류를 가린다. → 남은 참조 정리(불필요 데이터팩/설정 제거) 또는 해당 모드 복구.

3. **화이트리스트 미적용 + 온라인 모드인데 무방비.** `white-list=false`, `whitelist.json=[]`, `enforce-whitelist=false`. 8인 사설 협동 서버 컨셉인데 **누구나 접속 가능**. OP는 `a_ka1128` 1명. → `whitelist add`로 참가자 등록 후 `white-list=true`. (WorldEdit + 커맨드블록 활성 상태라 무단 접속 시 피해 큼)

4. **모든 진행 상태가 오버월드 `persistentData` NBT 단일 블롭.** 금고·마을·위협도·칭호·통계·봉화·원정 진행이 전부 한 곳(`world/.../level.dat` 계열 서버 NBT)에 저장. **손상되면 캠페인 전체가 증발**하고, `backup.bat`은 수동(더블클릭)이라 실서비스엔 부족. → (a) 자동 백업(스케줄러/재시작 훅), (b) 핵심 카운터(금고·진행도)를 주기적으로 `kubejs/config`에 JSON 스냅샷, (c) 서버 시작 시 무결성 로그.

### 🟡 Medium — 성능·밸런스

5. **틱 핸들러가 문자열 명령어를 많이 실행.** 여러 `ServerEvents.tick`이 `runCommandSilent`로 `execute/effect/particle/kill`을 돌린다. 특히 **정화 봉화**(`ls_beacon.js`)는 10초마다 `봉화 수 × 잡몹 9종`의 `kill` 명령을 발사 — 봉화가 늘면 명령 수가 곱으로 증가. → 명령어 대신 엔티티 API로 반경 스캔 1회 후 필터, 또는 봉화당 쿨다운 분산.

6. **`EntityEvents.spawned`가 모든 몹 스폰마다 실행**(`ls_mobscale.js`). 대공세·던전 웨이브로 몹이 쏟아질 때 스폰당 속성 조회/설정이 누적. 현재는 가볍지만 동시 스폰 폭증 구간에서 프레임 스파이크 요인. → 태그/카테고리 캐시, 보스·이미 처리된 엔티티 스킵 조기 반환 유지(이미 일부 적용됨).

7. **진행 스케일이 전역 공유(rf_progress) — 인원수 미반영.** 몹·보스 스케일이 파티 진행도에만 연동되고 접속 인원(1명 vs 8명)에 따른 보정이 없다. 8인 기준으로 맞추면 소수 접속 시 벽, 소수 기준이면 풀파티에서 심심. → 접속자 수 계수(예: 웨이브 몹 수·보스 HP에 `0.6 + 0.1×players`) 도입. They Are Billions/볼트도 인원 스케일이 핵심.

8. **경제 싱크·인플레 관리 부재.** 카지노(`ls_casino`)·현상금(`ls_bounty`)·공성 보상으로 Ducat 유입은 여럿인데, 상시적 대형 싱크(소모처)는 마을 발전 정도. 장기 시즌에서 Ducat 인플레 가능. → 봉화·상점·부활 비용 등 반복 싱크 추가, 발전 완료 후 재화 목적 재설계.

### 🟢 Low — 완성도·포장

9. **온보딩.** 커스텀 명령이 20개+(`/town /treasury /expedition /purifier /title /stats /riftnode /daynight /mobscale …`). FTB 퀘스트북이 뼈대를 잡지만, **명령어 치트시트/최초 접속 튜토리얼 NPC**(Easy NPC 이미 있음)로 진입장벽을 낮추면 상용감이 크게 오른다.
10. **클라이언트 포장이 바닐라.** 커스텀 리소스팩(로고·GUI·유물 텍스처는 현재 바닐라 아이콘 재활용: 정수=echo_shard, 열쇠=trial_key)·BGM·서버 아이콘(`server-icon.png`) 없음. `require-resource-pack=false`. → 서버 리소스팩 배포로 "다른 게임" 느낌 부여. 상용 팩과의 첫인상 격차 대부분이 여기서 발생.
11. **`neoforge-*-installer.jar`(6.9MB)와 설치 로그가 서버 폴더에 잔류.** 정리 대상.

## 5. 추가하면 좋을 것 (상용 벤치마킹)

- **볼트식 던전 변주 (from Vault Hunters).** 균열 열쇠 던전에 **테마·목표·모디파이어**(예: "제한시간 내 정수 수집", "무적 엘리트 처치", "저주: 재생 없음")를 랜덤으로. 지금은 웨이브 수만 다름 → 반복성 급상승.
- **플레이어 간 거래/기여 UI.** 공동 금고에 개인 지갑(SDM Economy)→금고 이체(`/treasury deposit`)를 실제 연결(코드 주석에 "리셋 후 예정"으로 이미 계획됨). 협동 경제의 마지막 조각.
- **시즌/무한 루프 옵션.** 현재는 피날레로 끝나는 단발 캠페인. 상용화하려면 **폐막식 후 자동 리셋 + 시즌 기록 이월(명예의 전당)**. `ls_config.js`의 튜닝 내성 구조가 이미 이걸 지원.
- **인원 스케일링**(4장-7 참조) — 상용 협동 게임의 기본기.
- **관전/사망 연출 강화.** Corpse 모드로 시체 회수는 있으나, 공성 전멸 시 "성역 함락" 연출·부활 대기 등 긴장 연출 추가.
- **디스코드 연동.** 이 워크스페이스에 이미 디스코드 봇 인프라(`DIscordBot/`)가 있음 → 공성 시작/격퇴, 보스 처치, 폐막식을 디스코드로 브로드캐스트하면 소규모 서버 몰입/재접속에 강력.
- **커스텀 리소스팩 + BGM**(4장-10) — 낮/저녁/밤/공성 페이즈별 음악 전환(낮밤 스크립트가 이미 페이즈를 알고 있음).
- **관리자 대시보드/치트시트 문서화.** 현재 커스텀 시스템 지식이 코드 주석에만 존재 — 운영자용 명령어·튜닝값 요약 문서 1장.

## 7. 수정 반영 (2026-07-24) — 로드맵 1, 4, 5

> ⚠️ 아래 변경은 **서버 재시작 후** 적용된다(새 jar + 새 데이터팩 파일). 재시작하면서 로그에 `apotheosis:book` ERROR가 사라졌는지, 봉화 정화가 정상 동작하는지 확인할 것.

### ✅ #1 — `lsrelics` 화살 크래시: 이미 수정됨 + 재발 방지 하드닝

- **상태 확인:** 크래시의 직접 원인(`ArrowStormManager`에서 화살 무기 인자에 EMPTY 전달)은 **이미 소스에서 수정**되어 있었고, 배포된 `server/mods/lsrelics-1.0.0.jar`(7/24 18:37 빌드)도 그 수정본이었다. 즉 크래시 자체는 이미 막혀 있던 상태.
- **추가 조치(재발 방지):** 이 버그는 **서버 전체를 다운시키는 계열**이라, 실수로 EMPTY가 다시 넘어와도 크래시가 안 나도록 공용 헬퍼를 추가하고 모든 화살 생성부를 그리로 모았다.
  - 신규: `moddev/lsrelics/.../LsArrows.java` — `firedFromWeapon`이 EMPTY면 자동으로 `null`로 정규화 후 `Arrow` 생성.
  - 경유로 변경: `ArrowStormManager`(별빛 폭풍), `StarBow`(평타), `RelicSkills`(유성 사격) 3곳.
  - **재빌드 완료 → 새 jar 배포**(7/24 18:49, `LsArrows.class` 포함). 기존 정상본은 `server/mods/lsrelics-1.0.0.jar.bak`로 보존.

### ✅ #4 — 로그/데이터 오염: 대부분 오진, 실제 잡을 것 하나만 처리

- **정정:** 초판에서 "제거된 모드의 잔재가 우리 데이터를 오염"이라고 했으나, 조사 결과 `world/datapacks`는 비어 있고 전역 데이터팩도 없다. 로그의 다음 항목들은 **우리 파일이 아니라 모드 jar 내부**의 정상적인 선택적-호환 노이즈였다:
  - `Error loading class: quark/arsnouveau/framedblocks/JEI...` → 다른 모드(supplementaries 등)가 **없는 모드를 optional mixin으로 참조** → 무해, 수정 불필요.
  - `CreateBuffetWorldScreen`, JEI Bookmark 등 **클라이언트 전용 클래스** → 서버엔 없음이 정상.
  - `expandeddelight:add_loot_sniffer_digging`, `quark:rune/shard 색상셋` → 모드 내부 데이터 문제 → 그대로 둠(비치명적).
- **실제 처리:** `apotheosis:book` 레시피만 ERROR 레벨로 떠서(결과물이 `patchouli:guide_book`인데 patchouli 미설치) 정리했다.
  - 신규: `kubejs/data/apotheosis/recipe/book.json` — 참조가 전부 유효하고 `neoforge:false`라 절대 등록되지 않는 no-op 레시피로 **덮어써 에러 로그 제거**. (나중에 patchouli를 넣으면 이 파일만 지우면 원본 복귀.)

### ✅ #5 — 정화 봉화 틱 최적화 (봉화 1기당 명령 9개 → 1개)

- **문제:** `ls_beacon.js`가 10초마다 **봉화 수 × 잡몹 9종**만큼 `kill` 명령을 돌려, 봉화가 늘수록 셀렉터 스캔이 곱으로 증가.
- **수정:** 정화 대상 9종을 엔티티 타입 태그로 묶고, `kill` 명령을 **봉화당 1개**로 축소.
  - 신규: `kubejs/data/last_stardust/tags/entity_type/purge.json` (정화 대상 원본 목록).
  - 변경: `ls_beacon.js` 정화 루프 → `kill @e[...,type=#last_stardust:purge,...]` 단일 명령. 제외 태그(`ls_siege`/`ls_captor`/`ls_rift_boss`)와 반경 동작은 그대로.
  - 대상 목록을 바꿀 땐 `purge.json`과 `ls_beacon.js`의 `PB_PURGE` 배열(문서용)을 함께 수정.
