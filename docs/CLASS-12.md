## 0. 이 직업은 왜 «소환사»인가

유저가 11번째를 정하면서 같이 정했다 — 근거는 조사 문서가 아니라 **재미**다.
그래서 이 문서는 「빈칸을 채운다」로 시작하지 않는다. 대신 **비어 있는 게 맞는지 먼저 본다.**

지금 11 종의 역할:

| 역할 | 누가 |
|---|---|
| 탱커 | 아틀라스 · 네메시스 |
| 힐러 | 히기에이아 |
| 지원 | 헤카테(저주) · 하르모니아(버프·원거리 딜) |
| 딜러 | 오리온 · 우라니아 · 크라토스 · 헬리오스 · 에레보스 · 쿠훌린 |

**딜러가 여섯이다.** 열두 번째를 또 딜러로 넣으면 일곱이 된다 — 숫자만 보면 넣을 자리가 아니다.

그런데 저 여섯은 **전부 「내가 때린다」**다. 소환사는 **「내가 아닌 것이 때린다」**로,
같은 딜러여도 손이 하는 일이 다르다. 정확히는 이런 자리다:

- **혼자여도 파티처럼 싸운다** — 인원이 안 모이는 날의 보험. 이 서버가 실제로 겪는 문제다.
- **자리를 잡는 딜러** — 다른 여섯은 «표적을 쫓는» 딜러다. 이쪽은 깔아두고 유지한다.
- **어그로를 나눈다** — 잔영이 맞는 동안 사람이 안 맞는다. 탱커가 없을 때 두 번째 보험.

⚠️ **가장 큰 위험도 여기 있다.** 소환수는 「가만히 있어도 딜이 나오는」 구조라,
잘못 잡으면 **제일 편하면서 제일 센 직업**이 된다. 대가를 어디에 둘지가 이 설계의 전부다
(→ §3).

## 1. 정체 — **이름은 유저 확정 대기**

| 항목 | 제안값 |
|---|---|
| 가호 키 | `mnemosyne` |
| 이름 · 별칭 | **므네모시네** · **먼저 간 이들을 부르는 자** |
| 역할 | **소환 지속 딜러** |
| 유물 | **므네메** — 「기억」, 므네모시네의 딸(가장 오래된 뮤즈 셋 중 하나). **등불** |
| 색 | `0x7FD8C8` 창백한 청록 — 꺼진 별빛 |
| 아이콘 | `✶` |
| 각성 체력 | 10 / 15 / 20 / 25 / **30칸** — 유물 중 가장 약하다 |
| 소환수 이름 | **별의 잔영** (프로토타입에 이미 이 이름으로 들어가 있다) |

**이름을 왜 므네모시네로 잡았나.** 이 소환수는 「기억의 여신이 불러낸 먼저 간 별지기들」이다.
`ls_relic.js` 의 여덟 `echo` 줄 — *「내 뒤에 일곱이 있었다. 마지막엔 아무도 없었다」* 같은 —
이 전부 **돌아오지 못한 세대**의 말이고, `STORY.md` 부록B 떡밥3 이 그 실을 이미 깔아뒀다.
소환사는 그 실을 **손에 쥐는** 직업이다. 새 설정을 만들지 않고 있는 것을 회수한다.

**대안 둘** (유저 취향 문제라 여기서 안 정한다):
- `asteria` **아스테리아** — 별똥별의 여신. 「떨어진 별을 다시 부른다」. 제목과 가장 가깝다
- `nyx` **닉스** — 밤. 「어둠이 삼킨 세계」 무드와 직결되지만 에레보스(어둠)와 겹친다

**왜 등불인가.** 지팡이는 이미 둘이다(우라니아 · 히기에이아). 등불은 **드는 물건**이지
휘두르는 물건이 아니라서, 「내가 안 때린다」가 외형으로 먼저 읽힌다.

## 2. 조작

| 키 | 이름 | 효과 | 쿨 | 해금 |
|---|---|---|---|---|
| **좌클릭** | **지목** | 별빛 파편 원거리 · **맞은 대상에 표식 5초** → 잔영 전부가 그리로 | — | 1성 |
| 패시브 | **별의 잔영** | **3기 상주 · 수명 없음** · 죽으면 15초 뒤 스스로 돌아온다 | — | 1성 |
| **R** | **호출** | 잔영을 눈앞으로 즉시 소집 + **6초간 잔영 피해 +40%** | 12초 | 1성 |
| **V** | **자리바꿈** | 조준한 잔영과 **위치를 맞바꾼다** (낙하 피해 면제 1.5초) | 9초 | 2성 |
| **C** | **흩어짐** | 잔영을 **전부 터뜨린다** — 기당 반경 4칸 피해 · 터진 것은 15초 뒤 복귀 | 20초 | 3성 |
| **X** | **여덟의 밤** | **8기를 부른다 · 15초** — 상주 3기는 그대로, 임시 5기가 더해진다 | 100초 | 4성 |

### 왜 「재소환 버튼」이 없나

소환사에서 제일 흔한 실패가 **「소환 → 죽음 → 재소환」의 무한 잡일**이다. 그건 조작이 아니라
관리다. 그래서 잔영은 **수명이 없고 스스로 돌아온다.** 플레이어가 고민할 것은
「어디에 둘까 · 언제 태울까」뿐이다.

⚠️ 대신 **깔아두고 방치하는** 플레이가 가능해진다. 그걸 막는 게 좌클릭 「지목」이다 —
표식이 없으면 잔영은 그냥 가까운 것을 치므로, **손을 놓으면 화력이 눈에 띄게 떨어지게** 잡는다.
(표식 대상 피해 +25% 같은 형태. 수치는 §4.)

### C 「흩어짐」 — 네메시스의 기세와 같은 문법

**자원을 태워 화력으로 바꾼다.** 잔영 3기가 곧 자원이고, 터뜨리면 15초간 화력이 0 이 된다.
「지금 터뜨릴까, 계속 때리게 둘까」가 매번 돌아오는 판단이다.

네메시스에서 R·C·X 가 기세 하나를 놓고 다투게 만든 것과 같은 설계다 —
**자원이 하나뿐이고, 쓰는 곳이 여럿이어야 «고를 것»이 생긴다.**

### X 「여덟의 밤」 — 로어가 먼저 있었다

여덟 별지기가 한 번에 돌아온다. 8 이라는 숫자는 밸런스가 아니라 **`ls_relic.js` 의 여덟 `echo`**
에서 왔다. 15초 뒤 전부 사라진다.

⚠️ **서버 부하가 여기서 결정된다.** 소환사 한 명당 상시 3 + 궁극 5 = **최대 8 엔티티**.
소환사 넷이 동시에 궁극을 쓰면 32 기다. 공성 중이면 그 위에 몹이 얹힌다.
**인게임에서 렉이 보이면 궁극을 5~6기로 줄인다** — 그림값보다 프레임이 먼저다.

## 3. 대가를 어디에 두는가 — 이 설계의 핵심

소환수는 **가만히 있어도 딜이 나온다.** 대가가 없으면 「제일 편하고 제일 센 직업」이 된다.
대가를 셋으로 나눠 걸었다.

**① 몸이 제일 약하다.** 체력 30칸 — 유물 중 최저(다음이 에레보스 32). 방어 속성도 없다.
잔영이 앞에 있는 동안은 안전하지만, **한 번 붙으면 제일 먼저 죽는다.**

**② 즉발이 없다.** 다른 딜러는 스킬을 누른 순간 피해가 들어간다. 잔영은 **날아가서 때려야** 한다.
도망치는 적, 순간이동하는 보스, 짧은 약점 창 — 전부 이쪽에 불리하다.
`WeaknessHandler` 의 약점 노출(5초)을 잔영이 놓치는 장면이 실제로 나올 것이다.

**③ 잔영은 죽는다.** 광역기를 쓰는 몹, 공성의 투석, 보스의 장판 — 잔영이 먼저 녹는다.
녹으면 15초간 화력이 0 이다. **잘 두는 것이 실력**이 된다.

⚠️ **③이 실제로 성립하는지가 제일 불확실하다.** 마인크래프트 몹 대부분은 **플레이어만** 노린다
(`NearestAttackableTargetGoal<Player>`). 잔영을 노리는 건 «맞고 반격하는» 몹뿐이다
(`HurtByTargetGoal` — 좀비·스켈레톤 등엔 있다).
**보스가 잔영을 아예 무시하면 ③은 대가가 아니라 공짜가 된다.** 인게임에서 먼저 볼 것.

## 4. 수치 — **전부 가정치다. 게다가 잴 방법이 없다**

### 지금 프로토타입 값

| | 값 | 비고 |
|---|---:|---|
| 잔영 체력 | 30 | 첫 시험에서 14 → 30 으로 올렸다 |
| 잔영 피해 | 14 | 5 → 14 |
| 수명 | 30초 | **설계에서는 «없음»으로 바꾼다** |
| 추적 반경 | 16칸 | |
| 목줄 | 24칸 | 넘으면 주인 곁으로 순간이동 |

### 겨누는 값

3기 상주 기준 **40~50 DPS**. 여기에 좌클릭(별빛 파편)과 C·X 를 더해 총합 **95 근처** —
8종 파티 평균 96.5 와 같은 대역.

⚠️ **각성 배율에 아직 안 묶여 있다.** `SummonManager.DAMAGE` 가 상수라 1성도 5성도 14 다.
`RelicSkills.power(stack)` 를 태워야 하는데, 잔영은 소환된 뒤 무기와 끊어지므로
**소환하는 순간의 성급을 엔티티에 적어둬야 한다**(`persistentData`).

### ⚠️ 측정 문제 — 이게 제일 크다

`/dummy` 는 **플레이어가 준 피해**를 잰다. 잔영이 준 피해는 `DamageSource.getEntity()` 가
벡스라 소환사 몫으로 안 잡힌다. **이 직업은 지금 구조로는 DPS 를 못 잰다.**

두 가지 길:
- `DummyManager` 가 `SummonManager.isSummon(attacker)` 이면 주인을 찾아 그 사람 몫에 더한다
- 또는 잔영 피해를 `LsDamage` 를 거치게 해서 출처를 주인으로 바꾼다 (위협도·축복까지 같이 맞는다)

**후자가 맞다.** 그래야 축복·기타 배수가 잔영에게도 일관되게 걸린다.
다만 그러면 잔영 피해가 소환사의 위협도로도 쌓인다 — 그건 오히려 맞다(→ §5).

## 5. 위협도 — 잔영은 어그로를 끌어야 하나

**끌면 안 된다.** 소환사가 잔영으로 어그로를 잡으면 **세 번째 탱커**가 된다.
이지스·네메시스가 도발과 위협도 배수로 자리를 잡아둔 판을 소환사가 공짜로 가져간다.

그런데 §4 의 결론(잔영 피해를 `LsDamage` 로 주인 몫에 넣는다)을 따르면
**잔영 피해가 그대로 소환사의 위협도가 된다.** 3기가 40 DPS 를 내면 위협도도 40/초다.
탱커가 이지스(114/초)라면 안 밀리지만, **탱커가 없으면 소환사가 맞기 시작한다.**

제안: **잔영 피해의 위협도 계수 ×0.5.** 딜은 온전히 주인 것이되 미움은 절반만.
`ThreatManager` 의 `HEAL_FACTOR` 와 같은 자리·같은 꼴이다.

⚠️ 이건 아직 **아무 근거 없는 숫자**다. 인게임에서 「소환사가 자꾸 맞는다」면 내리고,
「잔영만 때리고 소환사는 무시당한다」면 올린다.

## 6. 구현 — 무엇이 이미 있고 무엇이 없나

| 필요한 것 | 상태 |
|---|---|
| 소환수 엔티티 | ✅ `SummonManager` (벡스) |
| 주인 추적 · 목줄 · 표적 선택 | ✅ 있음 |
| 소환수가 사람을 안 때림 | ✅ `onSummonHit` |
| 사람이 소환수를 못 때림 | ✅ `onSummonHurt` |
| 몹 스케일링 제외 | ✅ `LSKubeBridge.isMonster` |
| **수명 없음 + 자동 복귀** | ❌ 지금은 `LIFE_TICKS = 600` 고정 |
| **각성 배율 연동** | ❌ 상수다 |
| **피해 출처를 주인으로** | ❌ 없음 (§4) |
| **좌클릭 지목 표식** | ❌ 없음 |
| **R·V·C·X** | ❌ 없음 |
| 유물 아이템 · 모델 · 텍스처 | ❌ 없음 |
| `ls_fate.js` · `ls_relic.js` · `ls_ascend.js` · `ls_title.js` 등록 | ❌ 없음 |

**절반은 이미 있다.** 프로토타입이 「소환수를 굴리는 데 필요한 함정」을 먼저 밟아둔 덕이다.

### 외형 — 벡스로 계속 갈 것인가

프로토타입은 바닐라 벡스다. 「꺼진 별이 남긴 잔영」이라는 설정에는 날아다니는 유령이 맞지만,
**벡스는 누가 봐도 벡스다.** 옵션 셋:

1. **그대로 간다** — 공짜. 「별의 잔영」이라는 이름과 파티클(SOUL_FIRE_FLAME + END_ROD)로 덮는다
2. **리소스팩으로 벡스 텍스처만 갈아끼운다** — 싸다. 단 **세계의 모든 벡스**가 같이 바뀐다
3. **커스텀 엔티티** — GeckoLib 은 있지만 **이 프로젝트는 커스텀 엔티티를 한 번도 등록해본 적이 없다.**
   진짜 벽은 코드가 아니라 에셋이다 — 자유 라이선스 대검 하나에 검색을 여섯 번 돌렸다

**1 로 시작해서 손맛을 먼저 본다.** 헤카테·하르모니아에서 모델 교체는 이미 두 번 해봤으니
나중에 갈아끼우는 건 어렵지 않다.

## 7. 먼저 확인할 것 — 설계보다 이게 먼저다

코드를 더 쓰기 전에 **인게임에서 세 가지**를 본다. 셋 다 이 설계의 전제를 무너뜨릴 수 있다.

1. **잔영이 실제로 맞아 죽는가** (§3 ③) — 보스가 무시하면 대가가 사라진다
2. **3기가 어느 정도 딜을 내는가** — 지금은 잴 방법조차 없다(§4)
3. **8기가 렉을 만드는가** — 궁극 규모가 여기서 정해진다

`/lssummon 3` 으로 지금 바로 ①②③ 을 다 볼 수 있다. **이 문서의 수치는 그 뒤에 고친다.**
