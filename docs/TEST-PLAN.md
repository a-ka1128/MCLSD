## 1. 제일 먼저 걸어둘 것 — 격노 «안 걸려야 정상» 시험 (10분, 방치)

**이게 이번에 고친 것 중 제일 중요하다.** 07-31 로그에서 **접속자 0명인데 보스가
+200% 까지 올라가 있었다.** 교전 판정이 아예 없어서 엔티티를 본 순간부터 시계가 돌았다.

실전 피해: 트와일라잇 구조물 보스나 도망친 보스가 로드된 청크에 서 있기만 해도 조용히
세지고, 나중에 그 앞을 지나간 사람이 **영문 모르고 한 방에 죽는다.**

시간이 걸리니 **먼저 걸어두고 2·3번을 하는 동안 흐르게 둔다.**

```
/lsgimmick ignis summon
```

소환한 뒤 **48칸 밖으로 물러나서 건드리지 않는다.** 10분 뒤:

```
/enrage status
```

| 봐야 할 것 | 판정 |
|---|---|
| 「교전 0초 · +0%」 또는 「대기 N초」 | ✅ **고쳐졌다** |
| 「교전 600초 · +10%」 이상 | ❌ 아직 벽시계로 센다 — `ls_enrage.js` `enEngaged()` 확인 |

그다음 **붙어서 실제로 때리며** 8분을 채우면 걸려야 한다. 8분을 기다리기 싫으면:

```
/enrage now 5
/enrage status     ← 「교전 N초 · +50%」
/enrage clear
```

> `/enrage now` 는 이미 검증됐다(07-31, 이그니스 14.0 → 22.4 → 14.0). **이번에 볼 건
> 「안 걸리는 것」이다.** 없던 기능이 아니라 없던 조건을 확인하는 것이라 헷갈리기 쉽다.

> ```
> 감쇄 전 50, 방어도가 20 을 뺌  →  실제 30
> 공격력 ×1.4 → 감쇄 전 70, 여전히 20 을 뺌  →  실제 50  =  ×1.67
> ```
> 빼는 몫이 그대로라 **남는 쪽만 곱해진다.** 짐작으로 올리면 반드시 과하게 올리게 된다.

**그래서 계기를 먼저 만들었다** (`BossDamageMeter.java`, 2026-08-11).
기존 전투 기록계는 **보스 체력만** 쟀다 — 몇 초에 죽었나, 체력을 얼마로 하면 60초가 되나.
「얼마나 아픈가」에는 계기가 통째로 없었다.

보고는 **세 곳에서 같은 포맷으로** 나온다 — 판이 어떻게 끝나든 값을 건지려는 것이다:

| 언제 | |
|---|---|
| 보스 처치 | `BossFightTracker.report` (로그에도 `[전투 피해]`) |
| **내가 죽었을 때** | 아픈지 재려면 맞아야 하고, 맞다 보면 **내가 먼저 죽는다** |
| **`/lsgimmick dmg`** | 30초 맞아 보고 그냥 읽는다 — 제일 싼 길 |

> 초판은 «보스 처치» 하나뿐이었다. 첫 시험에서 **강철거인에게 내가 죽었고**, 그래서
> 한 대도 못 건진 채 판이 끝났다 — **알고 싶은 바로 그 순간에 아무것도 안 나오는 계기**였다.

찍히는 모양:

```
▣ 강철거인 받은 피해 — 34대 · 감쇄 전 1820 → 실제 742 (한 대 평균 21.8 · 최대 47.0)
  내 최대 체력 80 → 3.7대에 죽는다 (한 대 = 최대 체력의 27%)
  방어도가 빼는 몫 31.7/대 — dmg% 를 올리면 실제 피해는 그보다 크게 는다
  120%→×1.49  130%→×1.98  140%→×2.47  150%→×2.96
```

**마지막 줄이 답이다.** 「예전 수준으로 되돌리려면 ×1.45」가 목표라면 저 표에서
그 배수에 가장 가까운 dmg% 를 고르면 된다 — 이 판의 실측에서 나온 값이라 짐작이 아니다.

```
/bossdiff global 100 <고른 값>
```

보스별로는 `ls_config.js` 의 `dmg`(지금 전부 100), 공성 잡몹은 `mobscale.dmg` 를 본다.
**한 번에 하나씩** 올리고 그때마다 한 판을 잰다.

> 로그 태그: `[전투 피해]` — 화면 줄은 OP 에게만 가고 스크롤에 금방 밀린다.

### 첫 실측 — 전제가 빗나갔고, 대신 다른 걸 찾았다 (2026-08-11 · 이그니스 · 이지스 5성)

```
▣ 이그니스 받은 피해 — 127대 · 감쇄 전 2507 → 실제 2371 (한 대 평균 18.7 · 최대 87.0)
  내 최대 체력 120 → 6.4대에 죽는다 (한 대 = 최대 체력의 16%)
  방어도가 빼는 몫 1.1/대
  120%→×1.21  130%→×1.32  140%→×1.42  150%→×1.53
```

**① 방어도가 거의 안 깎았다 — 1.1/대(5.4%).** 「방어도가 한 대에서 17~19 를 뺀다」를
전제로 이 계기를 만들고 「배수를 그대로 쓰면 과하다」고 경고했는데, **이그니스 상대로는
틀렸다.** 화염 계열이라 방어도가 아니라 화염저항이 막는 쪽으로 보인다.
→ **이 보스에 한해 `dmg% ≈ 실제 배수`다.** 보스마다 다를 수 있으니 **보스별로 재야 한다.**

**② 진짜 문제는 편차였다.** 평균 18.7 인데 **최대 87** — 4.7배다.

| | 지금 | dmg 140% |
|---|---:|---:|
| 최대 한 방 | 87 | **123** |
| 이지스 5성 (120 HP) | 72% | **원콤** |
| 원거리 5성 (80 HP) | **이미 원콤** | 원콤 |

평균만 보고 140% 로 올리면 「적당히 아파진다」가 아니라 **「한 대 잘못 맞으면 즉사」**가 된다.
**그래서 전역 배수를 올리기 전에 87 이 무엇인지부터 갈라야 한다.**

### 그래서 종류별 분해를 넣었다

`print` 가 피해 «종류»(damage type 등록 id)별로 갈라 찍는다. 상위 몇 개로 자르지 않는다 —
잘라 놓고 「나머지」로 뭉치면 그 안에 답이 숨는다.

```
종류별 (실제 피해 순)
 ├ cataclysm:ignis_fire       62대 · 실제 1420 (평균 22.9 · 최대 87.0) · 60%
 ├ minecraft:mob_attack       48대 · 실제  780 (평균 16.3 · 최대 31.0) · 33%
 └ minecraft:on_fire          17대 · 실제  171 (평균 10.1 · 최대 12.0) · 7%
```

**87 이 «예고 있는 큰 기술»이면 원콤이 설계일 수 있고, «평타에 섞인 것»이면 버그에 가깝다.**
둘의 처방이 정반대라, 이걸 모르는 채로 `/bossdiff global` 을 만지면 안 된다.

2페이즈(체력 50%)는 보라 + 보스 발밑 빨강 동시 = 어휘 조합의 첫 적용점.

### ⏸ 보류 중인 결정 — 강철거인 부활 규칙 (2026-08-11)

`mowziesmobs-common.toml` 의 **`reset_health_when_respawn` 은 `true` 로 놔뒀다** —

## 5. 실전 한 판 — 여기서만 알 수 있는 것

### 5-1. 보스 체력 4종 (4명·60초 목표)

**초시계도 계산기도 필요 없다.** 보스가 죽으면 스스로 낸다:

```
▣ 이그니스 처치 · 87.4초 · 4명 · 체력 7000 (실측 DPS 80)
목표 60초 → 권장 체력 4806   /bossdiff abs cataclysm:ignis 4806
```

운영 권한(2) 있는 사람에게만 보인다. **인원이 4명이 아니면 경고가 같이 뜬다** — 그 값을
그대로 넣으면 어긋난다. 다 재고 나면 `/bossdiff export`.

시간은 벽시계가 아니라 **교전으로 인정된 틱**이다. 죽고 돌아오는 시간은 안 센다.

### 5-2. 공성 한 판

- 위협도·성벽 HP·보상이 **재접속 후에도 남나** (이관 4단계 실전 검증)
- 마지막 웨이브에 **「균열의 선봉」** 이 나오나
- 예고 세 박자가 하루에 걸쳐 도나
- 격퇴/패배 후 **희망 게이지**가 움직이나

#### 5-2-A. 2026-08-07 수정 4건 — 실전에서만 보이는 둘 (10분)

> 나머지 둘(`/mobscale` 제외 · 인원 게이트)은 콘솔에서 이미 확인했다. 이 둘은 **살아 있는 공성**이
> 있어야 보인다. `/sanctuary here` 가 선행 조건이라 콘솔만으로는 못 돌린다.

**① 공성 종료 재진입 — 몹을 남긴 채 끝내기** (D절 8번)

```
/sanctuary here
/siege start
```

웨이브 몹이 **살아 있는 동안** `/siege end`. (이 명령은 `give_up` 을 넘긴다 — 결과가 무엇이든
청소 `kill` 은 똑같이 도니까 재진입 시험으로는 이게 제일 빠르다. 새벽까지 방치해도 된다.)

- 로그에 `[LS-SIEGE]` 결과 줄이 **정확히 한 줄**인가 — `GIVE_UP` 뒤에 `WIN` 이 또 찍히면 재진입이 남아 있다
- 끝난 뒤 `/siege status` 가 «진행 중»으로 남아 있지 않은가
- 월드에 `ls_siege` 태그 몹이 남지 않았나 → `/execute if entity @e[tag=ls_siege] run say 남음`
- 위협도가 **+1 만** 됐나 (`give_up` 은 1 회분) · 금고가 **-5 만** 됐나 — 재진입하면 승리 보상이 섞여 들어온다

**② 성벽 붕괴 = 패배** (D절 9번)

```
/wall set 0
```

그 상태로 새벽을 맞는다(`/time set day` 로 당겨도 된다).

- 「성벽을 잃었다」 타이틀이 뜨나 — 「동이 텄습니다」가 뜨면 강등이 안 걸린 것이다
- **위협도가 올랐나**(내려가면 안 된다) · 그 밤의 누적 보상이 **안 들어왔나**
- 희망 게이지가 **내려갔나**
- 로그에 `[LS-SIEGE] LOSE (wall broken) forfeited=N`
- 반대 방향도 한 번: 성벽이 성한 채 새벽 → 예전처럼 「동이 텄습니다」 + 보상 지급

> **첫 공세로 ②를 시험해도 강등 자체는 다 보인다** — 타이틀·위협도·보상 몰수·희망 전부 그대로 돈다.
> 다만 첫 공세는 `lose` 여도 **유물이 같이 해금된다**(해금이 여기 걸려 있어 밀리면 안 되기 때문에
> 일부러 열어 둔 예외). 그러니 「졌는데 유물이 깨어났다」가 나와도 정상이다 — 버그로 읽지 말 것.
>
> **순서 주의:** `/siege end` 는 `give_up` 이라 첫 공세를 **소비하지 않는다**(`result !== 'give_up'` 조건).
> 그래서 ①과 아래 5-2-B 를 먼저 돌리고, 첫 공세를 실제로 쓰는 ②를 마지막에 두면 한 번의 세팅으로 다 본다.

#### 5-2-B. 인원 게이트 — 관전자로 「아무도 없음」을 만든다 (3분)

`activePlayers()` 는 **관전자를 사람으로 세지 않는다.** 그래서 접속을 끊지 않고도 무인 상태를
만들 수 있다 — 서버를 내렸다 올릴 필요가 없다.

```
/gamemode spectator
/siege start
/time set day
```

- **「유물이 깨어난다」 타이틀이 안 떠야 정상이다.** 뜨면 게이트가 안 걸린 것이다
- `/relic` 로 확인 — 아직 못 받은 상태여야 한다
- 로그에 `[LS-SIEGE] first siege cleared` 가 **없어야** 한다
- 끝나면 `/gamemode survival` 로 되돌린다 — 이걸 잊으면 다음 시험이 전부 무인으로 판정된다

> 최종 보스 게이트(`[LS-FINALE] boss spawn deferred`)는 최종장에 들어가야 보이므로 여기서는 못 본다.
> 같은 `activePlayers()` 를 쓰므로 위가 통과하면 그쪽도 같은 판정을 탄다.

- **⭐ 몹 스케일링 C 확인** — 늑대·북극곰을 잡아 보고 **스케일링이 안 붙어야** 한다(좀비는 붙는다).
  로그에 `ls_mobscale:isMonster` 경고가 뜨면 다리가 실패하고 조용히 옛 동작으로 돌아간 것이다.
- **⭐ 부푼 몹 청소 — 돌아다니면서 가끔** `/mobscale fix`

  재시작마다 복리로 붙던 버그(D절 7)가 남긴 개체들이다. 07-31 시험 서버에서 **로드된
  청크 67기 중 30기가 부풀어 있었다.** 고친 코드는 스폰 훅에서 자동 복구하지만 구멍이 셋 있다:
  ① 티어 0 이면 훅이 일찍 return 한다 ② **늑대·철골렘·벌은 이제 비적대라 훅이 아예 안 본다 —
  그것들은 이 명령으로만 돌아온다** ③ 청크가 로드돼야 훅이 온다.

  그래서 **성역·마을·자주 가는 곳을 한 바퀴 돌면서 몇 번 실행**할 것. 여러 번 돌려도 안전하다
  (두 번째부터는 «0기»가 나온다). 관문을 깬 뒤에도 한 번 — 티어가 바뀌면 기준값도 바뀐다.
- **유물 ×1.8** — 네더라이트 검 60초 vs 1성 유물 60초 (성역 축복 안에서 통일)
- **부활 규칙** — 죽어보고 5초 무적 + **원거리 유물로** −25% 확인
  (근접만 보면 안 된다. 예전에 원거리·스킬이 통째로 새어나가고 있었다)
- ⚠️ **파나케이아는 더미로 재지 마라** · ⚠️ **솔라리스는 배율로 못 고친다**
  — 이유는 `DECISIONS.md` 1절 하단

「왜 이 값이지」로 다시 열리고, 그러면 같은 논의를 처음부터 한다 — 이 저장소에서 실제로
