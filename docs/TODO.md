## D. 코드를 훑다 발견한 이슈 (조사와 별개 — 확인/수정 권장)

> ### ⚠ KubeJS(Rhino) 함정 — 앞으로 스크립트 쓸 때 반드시 지킬 것
>
> **1. `try` 블록 안에서 `const`/`let` 을 쓰지 마라.** `var` 로 쓰거나 `try` 밖에서 선언한다.
> Rhino 가 `InternalError: TypeError: redeclaration of var X` 로 터진다. 특히 **같은 이름을
> 다른 `try` 블록에서 또 선언하면 확실히 터진다** (`try` 안의 선언이 상위 스코프로 누출된다).
> `var` 는 재선언이 합법이라 안전하다.
> · 실제 사례: `ls_voice.js` 의 접속 핸들러와 tick 핸들러가 `st`/`rf`/`day` 를 둘 다 선언 →
>   접속 인사·재접속 요약이 통째로 죽어 있었다. `ls_siege.js` 재타겟팅 2곳도 같은 상태였다.
> · **문법 검사(`node --check`)로는 절대 안 잡힌다** — 유효한 JS 라서 런타임에만 터진다.
>   서버 로그의 `[KubeJS Server]` 줄을 반드시 확인해야 한다.
>
> **2. 서버 스크립트는 전역 스코프를 공유한다.** 파일이 달라도 최상위 `function`/`const` 이름이
> 겹치면 나중에 로드된 쪽이 이긴다. 새 파일은 고유 접두사를 붙인다(`vc*`, `tw*`, `sf*`, `rf*`).
>
> **3. `runCommandSilent()` 의 반환값을 쓰지 마라 — 없다.** 시그니처가 `void` 다:
> `public default void kjs$runCommandSilent(java.lang.String);`
> 그래서 아래 관용구는 **처음부터 작동한 적이 없다.** 항상 `undefined` 가 들어갔다:
> ```js
> have = server.runCommandSilent(`clear ${name} ${item} 0`)   // ✗ 개수가 안 온다
> ```
> JS 에서 `undefined`·`NaN` 은 **모든 비교가 false** 라 부족 검사를 그대로 통과하고, 증상이 둘로 갈렸다:
> · 값이 저장까지 흘러가면 → `Cannot convert NaN to int` 로 **명령이 통째로 죽는다**(빨간 오류)
> · 비용 검사면 → **공짜로 통과한다** (정수 없이 유물 수령·관문 개봉·칩 없이 베팅)
> 5개 파일 전부 이 상태였다: `ls_town`·`ls_bounty`(크래시) · `ls_relic`·`ls_rift`·`ls_casino`(공짜 통과).
> **→ 개수는 인벤토리를 직접 읽는다. `ls_util.js` 의 `lsCountItem(player, id)` / `lsTakeItem(player, id, n)` 사용.**
> 저장 헬퍼도 `twInt()` 처럼 한 번 더 거르는 게 안전하다.
>
> **4. `kjs$` 접두사를 붙여 부르지 마라.** 자바 쪽 실제 이름이 `kjs$setMaxHealth` 여도
> 스크립트에서는 `setMaxHealth` 로 부른다. 붙이면 `Cannot find function` 으로 핸들러 전체가 죽는다.
> · 실제 사례: `ls_bossdiff.js` 가 `e.kjs$setMaxHealth()` 를 불러 **보스 난이도 조절이 통째로
>   무효**였다(체력·공격력 둘 다). 몹 스폰마다 에러가 찍히고 있었다.


> 조사 후보가 아니라, 코드를 읽으며 눈에 띈 것들. 착수 전 실제 인게임에서 재현 확인 권장.

1. **`ls_siege.js` — `const accrued` 재할당 (버그 의심, 도달 가능)**
   `finishSiege`에서 `const accrued = sfGetI(...)`(≈389행)로 선언한 뒤, `dawn` 분기(≈419행)에서
   `accrued = Math.round(accrued * REWARD_MULT)`로 **재할당**한다. `dawn` 경로는 "밤을 다 못 깨고 아침이 온"
   흔한 상황(`finishSiege(server,'dawn')`, 619행)이라 실제로 실행된다. KubeJS(Rhino)에서 const 재할당은
   런타임 TypeError를 던질 수 있음 → `let accrued`로 바꾸거나 새 변수 사용. **한 줄 수정, 우선 확인 권장.**

2. **`ls_beacon.js` — 정화 대상 목록 이중 관리(드리프트 위험)**
   실제 정화는 태그 `#last_stardust:purge`(`purge.json`)를 쓰고, 코드의 `PB_PURGE` 배열은 "문서용 원본"이다
   (주석에 명시됨). 대상 변경 시 **두 곳을 같이** 고쳐야 함 — 잊으면 조용히 어긋난다. 한쪽을 SSOT로 정리 검토.

3. **복구 커맨드 비대칭** · `ls_town`은 관리자 레벨 set/reset이 없다(위 B절과 동일). 인식 버그 시 수동 복구 불가.

4. **`main.js` 예제 잔재** · `server_scripts/main.js`·`startup_scripts/main.js`가 KubeJS 기본 "Hello, World" 로그를
   그대로 출력. 무해하지만 콘솔 노이즈 — 정리 권장.

5. **전역 심볼 결합** · 여러 스크립트가 파일 경계를 넘어 전역(`ttGrant`, `asStamp`, `BOSS_SET`, `LS_CONFIG`)을
   공유한다. 의도된 설계(공유 스코프)이고 잘 동작하지만, **로드 순서·오타에 취약**하다. 신규 스크립트 추가 시
   `priority` 주석 규칙(현재 `ls_config`=1000)을 문서로 고정해 두면 안전.
