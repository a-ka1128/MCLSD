내 클라와 서버는 이걸로 한 번에 맞춘다:


> 📄 **`.mrpack` 으로 통째로 내보낼 거면 `docs/RELEASE.md` 를 먼저 훑을 것.**

### A-2. 🔴 ~~월드 리셋~~ → **지금 월드로 간다** (2026-08-12, 유저 결정)

리셋은 2026-08-06 부터 예정돼 있었지만 **접었다.** 스폰 근처에 자연 생성된 **비행선**이 있고,
그걸 온보딩의 시작점으로 쓰기로 했다(§B-3) — 리셋하면 그게 사라진다.

**대신 두 가지가 따라온다:**

**① 리셋이 해 주던 청소를 손으로 해야 한다.** 지금 월드는 시험판이다 —
오늘만 보스를 여덟 번 소환하고 격노를 걸었다 풀었고 `/dummy` 더미가 곳곳에 서 있다.

```
/dummy clear                  훈련 더미
/lsgimmick clear              태그 붙은 시험 보스
/kill @e[type=...]            ⚠️ 바닐라 /summon 으로 부른 보스는 위로 안 지워진다
/enrage clear                 격노 잔재 (⚡ 표식으로 찾는다)
/bossdiff reset               시험용 오버라이드
/rkey clear · /vault reset    서약·금고 시험 진행도
```

계정도 시험 상태다 — `a_ka1128` 이 5성 유물을 들고 있고 가호·각성·금고가 다 차 있다.
`/fate reset` · `/relic revoke` · `/ascend set 1` 로 되돌린다.
**금고·마을 레벨·관문 진행도**도 시험값이 들어 있는지 `/town` · `/expedition` 으로 확인할 것.

**② 리셋을 기다리던 항목들의 처지가 바뀐다:**

| | 리셋 전제였을 때 | 지금 |
|---|---|---|
| **제단 자연생성** | 월드젠으로 심는다 | ❌ **불가능** — 구조물은 이미 생성된 청크엔 안 나온다. **손으로 짓는 수밖에 없다** |

### ① ✅ 성벽 — 지었다 (2026-08-12)

정사각 반경 60(한 변 120칸), 성역이 중앙. 진격 방향은 **성문 쪽(남)으로 고정**했다 —
`ls_config.js` 의 `wall.siegeAngle: 90`. `null` 로 두면 예전처럼 매 공성 무작위다.
각도는 `x=cos · z=sin` → **0=동 · 90=남 · 180=서 · 270=북**.

인게임에서 확인했다 — 몹이 성문 앞에서만, 성벽 33칸 바깥에서 나온다.

> ⚠️ **반경을 다시 키울 땐 시뮬레이션 거리를 같이 본다.** 공성 몹은 성벽이 «닿는 끝»에서
> 8칸 밖에 스폰되는데(`spawnRing = wallReach + 8`), 그 거리가 시뮬레이션 거리를 넘으면
> **몹이 스폰만 되고 틱을 안 받아 그 자리에 서 있는다** — 오류도 로그도 없이 밤이 지나간다.
>
> | 반경 | 정사각 (R×√2+8) | 원형 (R+8) |
> |---:|---:|---:|
> | 24 | 42칸 | 32칸 |
> | **60 (지금)** | **93칸** | 68칸 |
> | 120 | 178칸 | 128칸 |
>
> `/wall` 과 `/wall radius` 가 스폰 거리 > 시뮬레이션 거리이면 빨갛게 경고한다.
> 조용히 실패하는 종류라 반드시 보여야 한다.

### ② 🟡 마을 16단계 — 코드는 생겼고 «무엇이 자라는가»가 남았다

4트랙(방벽 ▦ · 공방 ⚙ · 성소 · 구역) × 4레벨 = **16단계**.
2026-08-13에 **구조물을 세우는 쪽은 만들었다**(`TownBuild` · `TownService.reconcile`).

```
/town anchor <트랙>   지금 서 있는 자리를 앵커로 (성역 기준 «상대» 좌표)
/town build <트랙>    지금 레벨 구조물을 다시 세운다 (파일을 고친 뒤에 쓴다)
```

구조물 파일은 `server/kubejs/data/lsrelics/structure/town/<트랙>_<단계>.nbt`.
자세한 절차와 함정은 **`docs/TOWN.md`** 「레벨이 오르면 구조물이 세계에 선다」에 있다.

> **남은 건 「무엇이 자라는가」다.** 공방은 2026-08-13 유저 결정으로 «단계만 오르고
> 구조물은 그대로» 가기로 했다 — 대신 철창에 문이 달려 안팎이 갈린다.
> 나머지 세 트랙은 아직 안 정했다.

### ③ 유물 제단이 lodestone 한 칸

**가호 12종 = 제단 12곳** (`ls_relic.js` 의 `RELICS` 키 수와 정확히 같다 — 예전에 「9~10곳」이라
적혀 있던 건 유물이 열둘로 늘기 전 숫자다). **손으로 짓고 `/relic altar <가호>` 로 등록**한다.

> ⚠️ **월드젠 경로는 막혔다.** 데이터팩 구조물은 «이미 생성된 청크»엔 안 나오므로
> 리셋을 접은 이상 쓸 수 없다(`TODO.md` C절). 손으로 짓는 게 유일한 길이다.

**건물은 하나만 만들어 12번 재사용하고 가호 색 블록만 바꾸는 게 낫다** —
일이 훨씬 적고, 「같은 양식의 제단」이 세계관상 더 맞는다.

#### 🟢 성벽 안에 모을 거면 **한 곳이면 된다** (2026-08-13)

가호별로 나누는 건 제단끼리 «멀 때» 값을 한다 — 「이 제단은 네 길이 아니다」가
찾아가는 수고를 전제로 한 문장이라서다. **성벽 안 한 자리에 열둘을 세우면**
그 문장은 뜻을 잃고 «내 것을 찾아 12번 우클릭하는» 일만 남는다.

```
lodestone 을 놓는다  →  그 위에 서서  /relic altar shared  →  우클릭해 확인
```

누가 우클릭하든 **그 사람의 가호에 맞는 유물**을 준다. 지급 규칙은 원래부터
가호를 보고 있었으므로(`rlGrant`), 바뀌는 것은 «어느 블록이 문을 여는가» 하나뿐이다.

> **보이는 맛은 건축으로 낸다** — 가운데에 «작동하는» 자석석 하나, 그 둘레에
> 가호 12색 기둥을 장식으로 세우면 그림은 그대로 남고 등록은 한 번으로 끝난다.
> 제단을 나눠 얻는 값은 «찾아가는 거리»지 «블록 개수»가 아니다.

`/relic altar` 는 공용이 등록돼 있으면 **「12개 중 몇 개」를 세지 않는다** —
안 그러면 「1/13」이 떠서 열둘을 더 지어야 하는 줄 알게 된다.

#### 가호별로 흩어 놓을 거면 (12곳)

절차는 제단 하나당 세 줄이다:

```
lodestone 을 놓는다  →  그 위에 서서  /relic altar <가호>  →  그 자리에서 우클릭해 확인
```

- 등록은 **lodestone 을 직접 찾아서** 한다(발밑 −1 · 선 자리 · −2 까지 훑는다).
  발밑에 없으면 등록을 **거부**한다 — 예전엔 발 높이를 그대로 저장해서 한 칸 어긋난 채
  «✔ 등록» 만 뜨고 우클릭이 영영 안 먹었다.
- 같은 블록에 두 가호를 등록하면 거부한다.
- **`/relic altar`** (인수 없이) 로 12개 중 몇 개가 등록됐는지·좌표가 어디인지 한 번에 본다.
  리터럴은 하나뿐이다 — **인수가 있으면 등록, 없으면 현황.** 잠깐 `altars` 를 따로 뒀다가
  한 글자 차이로 `/relic altars chiron` 이 튕겨서 합쳤다.

### ④ 공용 시각 기호 3종 · 최종문 실루엣

8각 별 / 꺼진 등불 / 검은 덩굴 — **어디에도 안 쓰이고 있다.** 이게 있어야
「여긴 별지기의 자리」와 「여긴 삼켜진 곳」이 말 없이 갈린다.
최종문(어둠의 첨탑)은 지평선에 보이는 목표물이라 **첫날부터 보여야 값을 한다.**

## B-3. ✅ 비행선 NPC 온보딩 (2026-08-13 검증 완료)

스폰 근처에 자연 생성된 **비행선**을 첫 세션의 시작점으로 쓴다.
**월드 리셋을 접은 이유가 이거다** — 리셋하면 그 배가 사라진다.

```
접속(비행선) → 프롤로그 자동 재생 → NPC 「난파선의 생존자」 클릭
    → 대화 (여기가 어디 / 당신은 누구 / 성역으로)
    → [ 성역으로 간다 ] → 텔레포트 + 연출 → 3초 뒤 가호 선택 화면
```

### 만든 것

| | |
|---|---|
| `Onboarding.java` | 보내고 · 떠나는 자리 연출 · 도착 연출 · 가호 화면. **절차 전부** |
| `/lsonboard <이름>` | NPC 가 부르는 입구. 관리자도 손으로 부를 수 있다 |
| `FateAutoOpen.openLater()` | 프롤로그 없이 가호 화면만 N틱 뒤에 |
| `ls_wreck_survivor.npc.snbt` | NPC 프리셋 — **데이터팩 파일이라 월드와 무관하게 산다** |

**절차를 코드에 둔 이유:** Easy NPC 대화 버튼은 커맨드를 한 줄씩만 부른다.
넷을 커맨드로 늘어놓으면 **절차가 데이터 파일 안에 흩어지고**, 순서 하나 바꾸려면
게임 안에서 NPC 를 편집해야 한다. **NPC 는 한 번만 부른다.**

**도착지는 성역 좌표 하나뿐이다**(`LSData`). 귀환석이 쓰는 것과 같아서,
첫 이동과 이후의 모든 귀환이 자동으로 같은 자리를 가리킨다.

### 세우는 법

프리셋은 **데이터팩 파일**이라 고친 뒤 `/reload` 를 해야 목록에 뜬다.

```
/reload
/easy_npc preset import default <탭>          ← 새로 하나 세운다
```

`import` 아래 갈래는 `default` · `world` · `custom` · `data` · `local` 다
(jar 의 `PresetImportCommand` 에서 확인). 우리 파일은
`kubejs/data/easy_npc/**default_preset**/humanoid/` 에 있으므로 **`default`** 다.
뒤의 이름·좌표·소유자는 **탭 완성으로** 고른다 — 인수 순서는 버전마다 바뀐다.

비행선 갑판에 세우고 — `NoAI` · `Invulnerable` · `Silent` 가 프리셋에 들어 있으니
안 움직이고 안 죽고 조용하다.

#### ⚠️ 프리셋 파일을 고칠 때 (2026-08-12에 겪음)

**고쳤으면 반드시 먼저 돌린다** — 아래 셋 다 인게임에서 이유를 안 알려준다:

```powershell
py tools/check_snbt.py server/kubejs/data/easy_npc/default_preset/humanoid/ls_wreck_survivor.npc.snbt
```

- 🔴 **`data` 바로 아래에 `id`(엔티티 타입)가 있어야 한다** — `id:"easy_npc:humanoid"`.
  **`PresetMetadata.entityTypeId` 는 별개다.** 그게 있어도 `data.id` 가 없으면 실패한다.
  인게임에는 §c「Unable to import default preset …」§r 한 줄만 뜨고, 진짜 이유는
  **서버 로그에만** 남는다 — `Missing entity ID tag in preset data`.
  **막히면 채팅 말고 `logs/latest.log` 를 본다.**
- **SNBT 에는 주석을 못 넣는다.** `//` 를 한 줄 넣으면 파서가 거기서 죽고,
  **프리셋이 목록에서 조용히 빠진다.** 설명은 이 문서에 적는다.
- **`ActionPermissionLevel` 은 `ActionEventSet` 의 «형제»다.** 안에 넣으면 무시되고
  기본 권한으로 떨어져 `/lsonboard`(권한 2)가 튕긴다 — 증상은 「대화는 되는데
  마지막 버튼만 아무 일도 안 일어난다」라 찾기 어렵다.
  실물은 `world/easy_npc/npcs/<uuid>.npc.nbt` 를 열어 보면 된다(gzip NBT).
- **`ON_INTERACTION` 에는 대화만 둔다.** 인게임에서 만든 NPC 의 기본값에는
  `OPEN_TRADING_SCREEN` 이 같이 들어 있어, 클릭하면 거래창이 함께 뜬다.
- **프리셋은 «통째로 갈아끼운다».** 모자란 칸만 채우는 게 아니다.
  그래서 `SkinData` 를 `Type:"DEFAULT"` 로 비워 두면 **가져오는 순간 스킨이 지워진다.**
  플레이어 스킨은 이름만으로는 안 붙고 `UUID`·`Timestamp` 까지 있어야 한다.

> 지금 파일은 인게임의 **린케우스**(`STEVE` + `HRSSamuelTTV` 플레이어 스킨)에 맞춰져 있다.
> 그래서 지금 세워 둔 NPC 에 그대로 가져와도 이름·스킨이 안 바뀐다.

### ⚠️ 세우기 전에 성역부터

`/sanctuary here` 가 안 돼 있으면 대화는 끝나는데 **아무 데도 안 간다.**
그 경우 `/lsonboard` 가 §c「성역이 아직 정해지지 않았다」§r 로 실패를 알린다 —
조용히 넘어가지 않게 해 뒀다. **첫 세션에 「대화는 끝났는데 아무 일도 안 일어났다」가 제일 나쁘다.**

### 같이 볼 것

- **스폰을 비행선으로 고정** — `/setworldspawn`. 안 하면 첫 접속이 엉뚱한 데서 시작한다
- **대사는 초안이다.** 세계관은 프롤로그(`FateAutoOpen.PROLOGUE`)와 맞춰 뒀지만
  말투·분량은 고쳐 쓸 자리다. 파일 하나만 고치면 된다
- 비행선을 **구조물(`.nbt`)로 떠 두면** 나중에 리셋하더라도 살릴 수 있다

## 세상에 흩어진 것 — 봉화 폐허 · 균열 노드

2026-08-13 추가. **둘 다 KubeJS 만 쓴다 — jar 재빌드도 클라 배포도 필요 없다.**
(`ls_ruin.js` · `ls_rnode.js`. 배치 상태는 `persistentData` 에, 장부는 모드에.)

### 왜 —— 「등록만 있고 실물이 없다」를 없앤다

점검에서 `/riftnode add` 가 **실물 검증이 없는 유일한 시스템**으로 드러났다.
제단은 자석석을, 봉화는 신호기를 확인하는데 노드만 이름을 그대로 믿었다.
그리고 봉화는 반대 문제였다 — 네더의 별 + 150 Ducat 이 필요해서 **한 기도 안 세워졌다.**
「영토 수복」이 설계의 중심인데 그 입구가 후반 콘텐츠 뒤에 잠겨 있었다.

### 대칭

| | 균열 노드 (어둠) | 봉화 폐허 (빛) |
|---|---|---|
| 예고 | **한다** — 방위 + 거리 | **안 한다** — 탐험하다 마주친다 |
| 출현 거리 | 64칸 | 128칸 (좌표를 모르니 넓게) |
| 링 거리 | 800 ~ 2500m | 400 ~ 2000m |
| 개수 | 한 번에 하나 | 6곳 (전부 밝히면 위협 하한 −3) |
| 하는 일 | 부수면 위협 하한 −2 · 별의 파편 2~3 | 켜면 정화 반경 + 하한 기여 + **전송석** |

> **어둠은 찾아오라고 알려주고, 빛은 스스로 찾아야 한다.**

### 균열 노드

```
/riftnode spawn [이름]   OP. 좌표를 굴리고 «장부에 먼저» 넣는다 — 예고된 순간부터 어둠은 진짜다
/riftnode site           실물이 어디 있고 수호자가 몇 기 남았는지
/riftnode abandon        OP. 실물만 포기(장부는 남는다 — 어둠을 공짜로 걷는 문은 안 만든다)
```

64칸 접근 → 균열이 열리고 **수호자**(정예 4 + 위더스켈레톤 6)가 나온다.
기둥 꼭대기 **균열핵**(crying_obsidian)을 부수면 끝. ⚠️ **수호자가 남아 있으면 안 부서진다** —
안 그러면 굴을 파고 핵만 캐는 게 최적 전략이 된다.

보상·최종장 개막은 **기존 `/riftnode remove` 로 흘려보낸다.** 여기서 다시 계산하지 않는다.

### 봉화 폐허

성역이 정해지면 **자동으로** 6곳이 흩어진다. 예고는 없다.

```
/ruin                 발견·점화 현황 (미발견 좌표는 OP 에게만 보인다 — 띄우면 탐험이 사라진다)
/ruin reroll <n>      OP. 자리를 다시 굴린다 — 누군가의 건축물 위에 떨어졌을 때의 탈출구
/ruin reset           OP. 전부 다시 (성역을 옮겼을 때)
```

128칸 안에 들어가면 폐허가 나타난다. 안에는 **꺼진 신호기**와 **전송석**이 있다.
신호기는 대좌 3×3 중 십자 네 칸이 부서져 있어서 **블록은 있는데 빛기둥이 없다** —
우클릭하면 그 네 칸이 메워지며 되살아난다. 「고친다」가 눈에 보이게.

점화는 **무료다.** 찾아온 것이 대가다. (`/purifier light` 의 150 Ducat 은
「아무 데나 세우는」 경로의 값이라 그대로 둔다. 장부는 둘이 같은 것을 쓴다.)

> ⚠️ **전송석이 판을 바꾼다.** 폐허를 밝힐수록 성역 밖 귀환망이 넓어진다 —
> 원정이 편해지는 대신 **밤의 긴장이 깎인다.** 웨이스톤의 성소 Lv1 게이트를
> 이 설계에 맞춰 다시 볼 것.

### ⚠️ 서버를 올리고 «제일 먼저» 확인할 것

```
/riftnode list      ← 이게 아직 돌면 Brigadier 병합이 된 것이다
```

`ls_rnode.js` 가 `ls_siege.js` 와 **같은 `/riftnode` 리터럴에 가지를 매단다.**
Brigadier 는 같은 이름의 노드를 합치지만(RootCommandNode.addChild), 만에 하나
한쪽이 덮으면 **초기화 절차의 `/riftnode add` 가 사라진다.**

## 초기화 — 오픈 직전에 한 번

「내 계정도 남들과 똑같이 시작한다」를 만드는 절차다.
**서버를 완전히 내리고 백업이 실제로 떨어진 걸 눈으로 본 뒤** 진행한다. 되돌릴 수 없다.

### ① 서버를 끈다 · ② 스크립트를 돌린다

```powershell
powershell -ExecutionPolicy Bypass -File tools\reset_open.ps1
```

백업 → 확인 → 삭제를 한 번에 한다. `RESET` 을 그대로 입력해야 진행한다.
**아래 넷 중 하나라도 걸리면 한 글자도 안 지운다:**

| 가드 | 왜 |
|---|---|
| 서버가 돌고 있다 | 켜진 채로 지우면 메모리의 옛 상태를 그대로 다시 써서 **조용히 되살아난다** |
| `tools/reset_restore.txt` 가 없다 | 성역·제단 좌표의 유일한 사본이다. 없이 지우면 되찾을 데가 없다 |
| `backup.bat` 이 UTF-8 이다 | cmd 배치 파서가 한글에서 어긋나 **zip 없이 「완료」만 찍는다** (아래) |
| 새 zip 이 안 생겼거나 1MB 미만 | 「백업했다」와 「백업 파일이 있다」는 다른 일이다 |

지우는 것 · 남기는 것은 스크립트가 실행 전에 화면에 다 띄운다.
`laststardust.dat` 은 zip 과 별도로 `backups/laststardust_<시각>.dat` 에 원본째 챙긴다 —
제단 좌표만 다시 보고 싶을 때 zip 을 풀어 뒤지지 않아도 되게.

> 🩹 **`backup.bat` 은 UTF-8 로 저장돼 있어서 한 번도 동작한 적이 없었다** (2026-08-13 발견·수정).
> cmd 는 배치 파일을 바이트 오프셋으로 읽는데, 한글이 UTF-8(3바이트)로 들어 있으면
> cp949(2바이트)로 세면서 어긋나 **뒷줄의 앞 글자를 먹는다** — `echo` 가 `cho` 로 실행된다.
> 끝까지 굴러가고 「백업 완료」까지 찍는데 zip 만 안 생긴다. `server/backups/` 가
> 계속 비어 있던 진짜 이유다. `reset_world.bat` 헤더가 경고하던 바로 그 함정을
> 옆 파일이 밟고 있었다. **`server/*.bat` 은 전부 cp949 로 저장할 것.**

### ③ 서버를 켜고 다시 등록한다

`laststardust.dat` 이 갖고 있던 «설정» 은 이게 전부다. 스크립트가 끝나면서 그대로 띄워 준다.
원본은 [`tools/reset_restore.txt`](../tools/reset_restore.txt) — **좌표를 바꿨으면 여기도 같이 고친다.**

```
/time set 0
/tp @s 5913 76 5897   ·  /sanctuary here    ← 좌표 인수가 없어서 가서 쳐야 한다
/wall radius 60
/relic altar shared 5887 85 5877            ← 이건 좌표를 받는다
/riftnode spawn 잿빛협곡                     ← add 아님. spawn 이 실물까지 만든다
/town hearth set                            ← 대장간 4단계 자리에 서서 (한 번도 안 찍었다)
```

선택 — 공방 앵커. 구조물을 안 세우기로 했으므로(§B-2 ②) **안 해도 된다.**
하려면 성역 기준 `+17, +9, -25` = **5930, 85, 5872** 에 서서 `/town anchor workshop`.

### ⑤ 확인

`/relic altar` 로 공용 제단이 ✔ 인지 · `/wall` 로 반경 60·시뮬레이션 경고 없음 ·
`/sanctuary info` 로 **위협도 0 · 「1일차」 · 첫 공세 미완료**인지 본다.
위협도가 5로 남아 있으면 `laststardust.dat` 이 안 지워진 것이다.

> ⚠️ `server/reset_world.bat` 은 **완전히 다른 물건이다.** 그건 `world/` 를 통째로 옮겨
> 지형부터 새로 만든다. 이 절차는 정반대 — 지형·건축·NPC·전송석을 그대로 둔다.

### 다시 등록 «안» 해도 되는 것

성벽 모양·진격 각도(`ls_config.js`) · 상점 품목(`ShopCatalog`) · NPC 프리셋 ·
세워 둔 건물과 전송석은 **파일이나 월드에 있지 `laststardust.dat` 에 없다.** 그대로 남는다.

> ⚠️ **`laststardust.dat` 한 파일에 성역·성벽·제단·마을·지갑이 다 들어 있다.**
> 그래서 지우면 ⑤의 재등록이 반드시 따라와야 한다. 자석석·건축물 같은 «블록»은 남는다.
>
> ⏸ **`world/entities/` 는 아직 안 정했다.** 지우면 시험 보스·더미가 싹 사라지지만
> **액자·갑옷거치대·보트도 같이 날아간다**(비행선 장식이 걸린다).
> 대안: entities 는 남기고 `/kill @e[type=!player,type=!item_frame,type=!armor_stand,type=!painting]`.
