## 한 줄 요약

각성(`ls_ascend.js`)이 지금은 **수치만** 올린다(피해 ×1.5→×3.0 + 직업별 체력).
여기에 **랜덤 부가효과**를 얹어 "같은 유물이라도 사람마다 빌드가 달라지게" 만든다.

핵심 논거: **랜덤이라 누구는 흡혈탱, 누구는 스킬딜이 된다 → 협동 시너지.**
3~6인 서버에서 8가호가 전부 정해진 성능이면 두 번째 시즌에 볼 게 없다.

### 「확률 강화 금지」와 충돌하지 않는 이유

`RESEARCH.md` 반면교사 표에 **"확률 재련/강화 실패 — 소그룹에서 분노만 남김(로스트아크)"** 가 있다.
별의 축복은 **실패가 없다.** 재료를 내면 무조건 성공하고, **무엇을 받느냐만** 랜덤이다.
잃는 게 없으므로 도박이 아니라 개성 부여다. 이 선을 넘지 말 것 —
**"강화 실패 시 등급 하락·파괴" 같은 건 절대 넣지 않는다.**

> UI 를 슬롯머신으로 만들 때 이 선이 특히 위험하다. 7절 주의 참고.

## 1. 슬롯 4칸 — 각성 단계마다 하나씩 열린다

| 성급 | 열리는 것 |
|---|---|
| 1성 | — |
| **2성** | **상의칸** (방어 8종 중 1) |
| **3성** | **무기 1번** (무기 10종 중 1) |
| **4성** | **하의칸** (방어 8종 중 1) |
| **5성** | **무기 2번** (무기 10종 중 1) |

초판은 3·5성에만 줬는데 그러면 2·4성이 빈손이었다. 넷으로 나누니 **각성 한 단계마다 눈에 보이는 것이 하나씩** 생긴다.

**중복 금지 — 축 안에서만 적용된다.**
무기 2칸끼리 같은 게 안 나오고, 방어 2칸끼리 같은 게 안 나온다.
무기와 방어는 목록이 아예 다르므로 서로 간섭하지 않는다.

```
조합 = C(10,2) × C(8,2) = 45 × 28 = 1,260 가지
```

## 3. 방어 8종 — 상의·하의에 붙는다

| 축복 | 범위 | 효과 |
|---|---|---|
| 수확 | **4~8%** | 처치 시 최대 체력의 그만큼 회복 |
| 가시 갑주 | **15~25%** | 받은 피해의 그만큼 반사 |
| 불굴 | **15~25%** | 체력 30% 이하일 때 받는 피해 감소 |
| 별빛 보호막 | **4~8%** | 피격 시 최대 체력의 그만큼 흡수 (5초 쿨 · **누적 상한 최대 체력 20%**) |
| 별빛 과포화 | **25~45%** | 초과 회복이 흡수 실드로 (상한 최대 체력 30%) |
| 질주 | **12~22%** | 3초간 안 맞으면 이동속도 증가 · 피격 시 초기화 |
| 재생 | **2~4%** | **4초마다** 최대 체력의 그만큼 회복 (전투 중에만) |
| 원한 | **8~14%** | **최근 5초 내 나를 때린 적**에게 주는 피해 증가 |

### 가른 기준

**「내가 가하는 것」 = 무기 · 「나에게 일어나는 것」 = 방어.**
수확(처치 트리거)과 원한(피격 트리거 → 피해)만 경계에 있는데, 둘 다 **방아쇠가 방어 쪽**이라 방어로 보냈다.
수확은 흡혈과 겹치지 않게 하는 효과도 있다 — 무기엔 지속 흡혈, 방어엔 처치 보상.

### 보류 3종 (Java 훅이 더 필요)

**운석 파편**(공격 시 8% 확률 별똥별 낙하) · **별의 도약**(스킬 사용 시 짧은 대시) ·
**재림**(처치 시 8% 확률 스킬 쿨 즉시 초기화).

18종이면 조합이 이미 1,260가지다. 굴려 보고 축이 비면 붙인다.
※ 「운석 파편」은 원래 「별똥 파편」이었다. 재화 **별의 파편**과 헷갈려서 개명했다(2026-08-08).

## 4. 시너지 지도

```
무기 × 무기
  흡혈 × 치유 증폭         회복량 자체가 증폭된다
  별빛 증폭 × 공명          스킬을 세게, 자주
  공명 × 여운              스킬 → 평타 강화 → 스킬 루프
  연쇄 × 흡혈              다타 = 회복 폭증 (군집 한정)
  연쇄 × 출혈              다수에 도트
  별의 낙인 × 출혈          표식이 도트까지 증폭

무기 × 방어
  치유 증폭 × 재생 / 수확    받는 회복 증폭
  치유 증폭 + 흡혈 × 과포화   3피스 — 넘친 회복이 실드로
  별의 낙인 × 가시 갑주      반사 피해도 표식을 탄다
  연쇄 × 수확              군집 처치 수 → 상시 만피

방어 × 방어      ← 2칸이 되면서 처음 열린 축
  재생 × 과포화             만피에서 재생이 전부 실드로
  원한 × 가시 갑주          「맞으면 이득」
  불굴 × 별빛 보호막         저체력 버티기
  별빛 보호막 × 과포화       실드 이중
```

## 5. 저장 — 플레이어에 둔다

**각성 성급이 이미 그렇게 동작한다.** `LS.star(server, uname)` 이 원본이고,
`asStamp()` → `/lsrelic star N` → `LSCommands.setStar()` 가 **인벤토리의 모든 유물에 복사**한다
(`LSCommands.java:552`). 아이템 태그는 사본이지 원본이 아니다.

축복도 같은 구조로 간다. 그래서 공짜로 따라오는 것들:

| | |
|---|---|
| **스틱스(쌍단검)** | 칼 두 자루를 들어도 축복이 두 배가 안 된다. **전용 예외 코드가 한 줄도 없다** |
| **유물 분실** | `/relic` 재지급 후에도 축복이 남는다 (성급이 이미 그렇다) |
| **복제** | 아이템을 복제해도 축복이 안 불어난다 |
| **갑옷 교체** | 가죽→네더라이트→모드템으로 갈아입어도 **안 사라진다** ← 이게 핵심 |

> **왜 Curios 부적을 버렸나** — 초판은 「갑옷은 갈아입으면 축복이 소멸한다」는 이유로
> 부적을 골랐다. 저장을 플레이어로 옮기면 그 문제가 원인부터 사라진다.
> 부적 아이템·텍스처·슬롯 등록이 통째로 필요 없어졌다.

**장비는 「어느 칸을 굴리는지」를 가리키는 지시자다.** 제단 UI 에 유물을 올리면 무기칸,
상의를 올리면 상의칸, 바지를 올리면 하의칸. 스틱스는 아무 단검이나 올리면 된다.

## 6. 다시 뽑기 — 두 축

| | 무엇을 | 비용 | 어디서 나오나 |
|---|---|---|---|
| **종류 리롤** | 무기 10종 / 방어 8종 중 어느 축복인가 | **별의 파편** 1 / 2 / 3 (3·4·5성) | 공성 격퇴 · 보스 · 정예 현상금 |
| **수치 리롤** | 그 축복의 퍼센트 | **별먼지** 3 / 5 / 8 (3·4·5성) | 구조물 상자 |

- 값은 **성급별 고정**이다. 반복해도 안 오른다.
- **종류를 바꾸면 수치도 같이 다시 굴린다.** 안 그러면 수치를 최대로 만들어 놓고
  종류만 갈아끼우는 「최댓값 유지 쇼핑」이 된다.
- 두 재화가 서로 다른 플레이를 요구한다 — **파편은 전투, 별먼지는 탐험.**
- **희귀도는 없다.** 18종이 같은 값어치로 맞춰져 있으므로 균등 추첨이다
  (초판의 ⭐/⭐⭐ 가중치는 폐기 — `DECISIONS.md` 4-6).

### 수치 굴림 — 성급이 확률을 정한다

```
u = random()^k
값 = 최소 + (최대 - 최소) × u
```

| 성급 | k | 평균 위치 | 하위 20% 확률 | 상위 20% 확률 |
|---|---|---|---|---|
| **3성** | 2.5 | 28.6% | **52.5%** | 8.5% |
| **4성** | 1.0 | 50% | 20% | 20% |
| **5성** | 0.4 | 71.4% | **1.8%** | **42.8%** |

흡혈(6~11%)로 보면 — 3성은 절반 넘게 `6.0~7.0%` 가 뜨고, 5성은 `10.0~11%` 가 2~3번에 한 번 뜬다.

**이게 노가다 브레이크를 겸한다.** 3성에서 최댓값이 뜰 확률이 1/N 이 아니라 1/N² 다.
하한을 막지 않으므로 「운 좋았다」는 순간은 남는다.

**방어 축복도 유물 성급을 그대로 쓴다.** 방어에 별도 성장 축을 두면 시스템이 둘이 된다 —
저장이 플레이어 단위라 성급 하나가 네 칸 전부를 들어 올리는 게 자연스럽다.

`k` 와 18종 범위표는 **`BlessingCatalog.java`** 에 있다 (`ls_config.js` 가 아니다 — 9절).

## 7. 전용 UI — 별의 제단

`/bless` 로 연다. **위치 제한은 없다.**

> 초안은 「제단 근처에서만」이었는데, 그 제단(`ls_relic.js:123`)은 **가호별 유물 제단**이라
> 별개의 물건이다. 거기에 묶으면 축복이 「내 직업 제단까지 걸어가야 하는 것」이 되고,
> 근처 판정용 블록을 새로 만들어야 한다. 마을 화면도 키 하나로 어디서나 열린다 —
> 같은 성격(공용 시설)이니 같은 규칙으로 둔다. **문은 위치가 아니라 마을 단계다**(아래).

### 해금 — 마을이 열어준다

| 마을 | 무엇 |
|---|---|
| **공방 Lv2 「대장간 지원」** (450 Ducat · 철블록 24) | **제단이 열린다.** `TownCatalog` 의 `forge` 플래그 |
| **성소 Lv4 「성역의 가호」** (2000 Ducat) | **제단 강화** — 수치 리롤 비용 −1 (`blessing` 플래그) |

`Level` 레코드의 `flag` 필드와 `TownData.flag(key)` 조회가 이미 있었고 **아무도 읽지 않고 있었다** —
해금 배선이 예약만 된 채 놀고 있었다. 그걸 쓴다.

공방 2에 단 이유는 **시기**다. 축복 슬롯이 2성 각성부터 열리는데 성소 4(2000 Ducat)는 최후반이라
슬롯이 한참 잠긴다. 공방 2는 450 Ducat 이라 초중반에 닿는다.

> 슬롯은 열렸는데 제단이 아직 없으면 **마을을 가리키는 안내**를 띄운다 — 「버그인가?」가 아니라
> 「저기로 가면 되는구나」가 되게. 성급 부족 안내와 같은 방식이다.
>
> ※ 성소 Lv4 의 이름이 원래 **「별빛 축복」**이었다. 이 시스템(**별의 축복**)과 인게임에서
>   구분이 안 돼서 **「성역의 가호」**로 개명했다 (2026-08-08 · lang 값만 변경, 키는 유지).

```
┌─ 별의 제단 ────────────────────────────────┐
│      ┌────┐            ┌────┐              │
│      │ 🗡 │            │ ✦  │              │   장비칸 = 굴릴 슬롯 지정
│      └────┘            └────┘              │   재료칸 = 별의 파편 / 별먼지
│      장비                재료                │
│                                            │
│   ╔══════════════════════════════════╗     │
│   ║  ✦  흡    혈          9.2%       ║     │
│   ║     6~11 중 상위 20%              ║     │
│   ║              [종류]  [수치]       ║     │
│   ╟──────────────────────────────────╢     │
│   ║  ✦  ───  비어 있음  ───           ║     │
│   ╚══════════════════════════════════╝     │
│                                            │
│         [    축   복   하   기    ]          │
│   [ 인벤토리 3×9 + 핫바 ]                    │
└────────────────────────────────────────────┘
```

**굴림은 서버가, 연출은 클라가.**

```
클라  [축복하기] ─────────────────▶  BlessPayload(slot)
서버                                  ① 검증 (재료·성급·중복금지)
                                      ② 굴림 (k 곡선)
                                      ③ 저장 + 재료 소모   ← 여기서 이미 확정
      ◀───────────────────────────  BlessResultPayload(종류, 값, 백분위)
클라  2초 스핀 → 감속 → 착지
```

결과는 굴림 즉시 확정이라 **연출 도중에 창을 닫아도 안 날아간다.**
채팅에도 한 줄 남긴다 — 곡선이 안 보이면 「버그인지 운인지」를 못 가린다:

```
✦ 별의 축복 — 흡혈 9.2%  (6~11 중 64%)
  5성 굴림: 상위 20% 확률 43%
```

`/mobscale`·`/siege status` 가 이미 쓰는 방식이다.

### ⚠️ 주의 — 슬롯머신은 도박 UI 와 생김새가 같다

### ⚠️ 되먹임 세 곳 — 전부 「오류 없이 조용히 망가지는」 종류다

축복 중 셋(**연쇄·가시 갑주·출혈**)이 *진짜 피해를 새로 만든다.* 그 피해가 다시 축복 이벤트를
지나므로 막지 않으면 스스로를 먹인다. 셋 다 예외가 안 나고 로그도 안 남는다:

| | 막지 않으면 | 어떻게 막았나 |
|---|---|---|
| **연쇄** | 주변 적 → 그 주변 적 → … 몹이 몰린 곳에서 **지수적으로** 터진다 | `inSplash` 깃발 — 파생 피해는 축복 처리를 통째로 건너뛴다 |
| **가시 갑주(대 몹)** | 반사가 다시 축복을 태운다 | 같은 깃발 |
| **가시 갑주(대 사람)** | A→B 반사→A 반사→… **서버가 멎는다.** 몹은 축복이 없어 안 걸리지만 사람끼리는 걸린다 | 깃발을 «받는» 쪽(`onIncoming`)에서도 본다 |
| **출혈** | `BleedManager.apply` 가 이미 걸린 대상의 시간을 «갱신»한다 → 출혈 틱이 또 출혈을 걸어 **영구 지속** | `BleedManager.LABEL` 로 자기 도트를 알아본다 |

`inSplash` 는 파생 피해에 처형자·관통 같은 배율이 **두 번 곱해지는 것**도 같이 막는다 —
연쇄는 「이미 계산된 피해의 몇 %」여야 한다.

깃발은 **이전 값을 복원한다**(`derived()`). 그냥 `false` 로 되돌리면, 연쇄가 도는 중에 가시가
겹쳐 발동했을 때 안쪽 `finally` 가 깃발을 내려버려 **남은 연쇄 대상들이 다시 축복을 탄다.**
`LsDamage.hit` 이 `prev` 를 들고 있는 것과 같은 이유다.

가시 갑주의 반사는 **불굴로 깎이기 «전»** 값을 쓴다. 깎인 값을 쓰면 둘을 같이 낄수록 반사가
줄어 **두 축복이 서로를 깎는다**.

**기준선이 187.4 / 186.7 로 0.4% 차이.** 3기를 세우니 오히려 판간 편차가 줄었다

|---|---:|---:|

⚠️ **±15% 폭이 남았고, 그건 측정 방법 탓이다.** 무보정 두 판의 평타 타수가 68/63 으로
8% 벌어졌는데 뺄셈으로 읽으니 그 오차가 증폭됐다.

**고쳤다**: 연쇄 피해에 **「연쇄」 이름표**를 달았다(`BlessingEffects.splash`).
예전엔 맨 `hurt` 라 이름표 없이 **평타 칸에 섞였다.** 「출혈」은 이름표가 있어 한 줄로 딱
읽혔던 것과 대비된다.

#### ✅ 이름표를 단 뒤 재측정 — **16.03%** (설계 16%)

```
연쇄   1,344 · 22.4 DPS · 128타 평균 10.5
평타   4,191 · 69.9 DPS ·  64타 평균 65.5
```
`10.5 ÷ 65.5 = 16.03%`

> **이게 이 문서에서 제일 값어치 있는 교훈이다.**
> 뺄셈으로 읽던 같은 효과가 **16~21%** 였는데, 이름표를 다니 **16.03%** 로 떨어졌다.
> 기준선을 빼는 방식은 두 판의 회전 차이를 그대로 증폭한다. **파생 피해는 이름표를
> 달아 같은 판 안에서 평타와 비교할 것** — 그러면 판간 편차가 아예 안 섞인다.

⚠️ 그 판에서 **일도양단이 814.7** 로 나왔다(기준 740.6 × 1.100 — `pierce` 의 서명과
정확히 같다). `weapon_2` 슬롯에 뭔가 남아 있을 가능성이 있다(5성이면 열려 있고,
「최초 부여는 무료」였다). **다음 측정 전에 `/bless status` 로 확인할 것.**
연쇄 값 자체는 같은 판 안 비교라 영향 없다.

이동속도라 DPS 리포트에는 안 잡히지만, **어트리뷰트 모디파이어라 값이 그대로 읽힌다.**
유물을 들 필요도 없다 — 축복은 아이템이 아니라 플레이어에 저장되고, 오히려 유물 자체가
이동속도를 주는 게 있어서 **맨손이 깨끗하다.**

```
/bless clear <닉네임>
/bless set chest sprint 22
/attribute @s minecraft:generic.movement_speed get                                  → 3초 뒤 0.122 (기본 0.1)
/attribute @s minecraft:generic.movement_speed modifier value get lsrelics:blessing_sprint  → 0.22
/damage @s 1                                                                        → 다시 0.1
```

모디파이어 조회는 **꺼져 있으면 「그런 모디파이어 없음」 에러**가 난다 — 그 에러가 꺼짐 판정이다.

> 📌 **붙고 떨어지는 데 최대 1초가 더 걸린다.** 검사 루프가 20틱마다 돈다
> (`BlessingEffects.onServerTick`). 설계는 3초 창인데 실제로는 **3~4초**이고,
> **맞은 뒤에도 최대 1초는 빠른 채로 남는다** — 도망치는 쪽에 유리하게 기운다.
> 틱 예산을 아끼려고 둔 것이라 지금은 그대로 두지만, 도주가 세다고 느껴지면
> 떼는 쪽만 매 틱 검사로 바꾸면 된다.

> 바닐라 달리기(+30%)는 `ADD_MULTIPLIED_TOTAL` 로 따로 곱해진다 —
> 달리는 중 조회하면 `0.1 × 1.22 × 1.3 = 0.1586`. 정상이다.

### 계측기에 더한 것들 (이번 묶음에서 필요해서)

| | 왜 |
|---|---|
| `/dummy hp <값>` | 체력 비율 축복(`executioner`·`harvest`)이 영원히 발동을 안 했다 |
| `/dummy hit <피해> [주기]` | 맞아야 도는 5종을 아예 못 쟀다 |
| 회복 / 보호막 줄 | 회복 계열 4종이 리포트에 안 잡혔다 |
| 「축복 회복 / 자연 회복」 분리 | 재생(0.34 HPS)이 배경 회복에 묻힌다 |
| 보호막을 **까는 자리**에서 셈 | 밖에서 관찰하면 같은 틱에 소모돼 순증이 0 이다 |
| 「원본 → 감쇄 전 → 실제」 | **불굴은 이 줄 없이는 못 잰다.** 가시의 분모이기도 하다 |
| `/dummy stop` 도 콘솔에 남김 | 손으로 끊은 판이 서버 로그에 한 줄도 안 남았다 |
| 연쇄·가시에 이름표 | 평타 칸에 섞여서 뺄셈으로 역산해야 했다 |

> **이 묶음의 교훈은 하나다.** 축복 18종 중 **설계가 틀린 것은 없었다.** 나온 문제는 전부
> **구현**(출혈 2건 · 이름표 2건)과 **계측기**(위 8건)였다. 「값이 이상하다」가 나오면
> **재는 자를 먼저 의심할 것.**

#### 측정 절차

원하는 축복을 굴려서 기다릴 필요가 없다 — **값을 생략하면 최댓값이 박힌다:**

```
/bless set weapon_1 <id>        ← 슬롯: chest · weapon_1 · legs · weapon_2
/bless clear <플레이어>
```

**한 축복당 「축복 없이 1판 → 그 축복만 1판」.** 차이가 곧 실측 퍼센트다.
그리고 **게볼그 앵커를 앞뒤로 끼운다**(`DECISIONS.md` 1-F) — 안 그러면 그날 캐릭터 상태가
그대로 섞여 들어간다.

| 묶음 | 준비 | 대상 |
|---|---|---|
| ① 기본 | `/dummy spawn` · `armor 0` | `pierce` `amplify` `resonance` `afterglow` `brand` `bleed` |
| ② 다중 표적 | 더미 **3기** | `cleave` |
| ③ 방어도 | `/dummy armor 10` | `pierce` (방어도 0 에선 절반만 나온다 — 진짜 값은 여기서) |
| ④ 저체력 | `/dummy hp 3000` | `executioner` `harvest` |
| ⑤ 피격 | `/dummy hit 20 30` | `barrier` `thorns` `resolve` `grudge` `sprint` |
| ⑥ 회복 | ⑤ 와 같이 | `lifesteal` `mend` `overflow` `regen` |

⑤·⑥ 은 같은 판에서 같이 잡힌다 — 맞아야 회복이 도는 것들이라 조건이 겹친다.
